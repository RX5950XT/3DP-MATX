# 列印參數與擺位（Bambu Lab A1／0.4 mm／PETG，第十四輪）

本頁是第十四輪 8 種 STL 的列印交付。逐件計畫唯一來源為
`腳本/列印擺位.py::PRINT_PLAN`；支撐開關直接讀所引用 process preset 的
`enable_support`，不另維護第二份清單。

| PETG @ 1.28 g/cm³ | **≈ 1663 g** |
| 採購 | **至少 2 捲 1 kg** |

1081.3 cm³ 只用來比對每種 STL 的幾何總量，買料必須看 1300.2 cm³。支撐、purge 與報廢量由真實切片／實印決定，
未加進上表。

## STL 實測

懸空定義為法向朝下、與水平夾角大於 45°，且不在首層的 STL 三角形面積；床接觸是
`z = zmin ±0.2` 的朝下面積。支撐 footprint 以普通支撐外脹
`support_object_xy_distance 0.35 + support_line_width 0.42 = 0.77 mm/邊` 計算
（第十四輪：0.20 → 0.35，見下節「脫模間隙的上限是床」）。
無支撐件只量裸件投影。

| 件 | 裸件 XYZ mm | 懸空 mm² | 床接觸 mm² | 實際佔床 mm | 餘量/邊 | 支撐 |
|---|---|---:|---:|---|---:|---|
| Chassis | 252.68 × 252.85 × 180.12 | 5951.7 | 62879.4 | **254.22 × 254.39** | **0.81** | 開 |
| Top | 250.48 × 247.35 × 6.00 | 5054.5 | 56618.4 | 252.02 × 248.89 | 1.99 | 開 |
| Front | 252.68 × 180.12 × 67.76 | 683.4 | 17614.5 | 252.68 × 180.12 | 1.66 | 關 |
| HDD Rack | 249.68 × 103.60 × 128.40 | 12661.3 | 19580.4 | **247.88 × 247.88**（45°） | 4.06 | 開 |
| HDD Tray | 185.00 × 107.60 × 29.80 | 1409.8 | 19675.2 | 185.00 × 108.37 | 35.50 | 開 |
| PCIeBlank | 18.42 × 120.02 × 9.60 | **0.0** | 2180.8 | 18.42 × 120.02 | 67.99 | 關 |
| PCIeBar | 81.86 × 21.55 × 11.00 | 110.3 | 1629.2 | 81.86 × 21.55 | 87.07 | 關 |
| MB_Screw | 8.00 × 9.24 × 8.97 | 31.8 | 38.5 | 8.00 × 9.24 | 123.38 | 關 |

A1 本機 profile 為 256 × 256 × 256，`bed_exclude_area = []`。最緊的是 Chassis 普通支撐
footprint，剩 0.81 mm/邊，通過腳本門檻 0.75 mm；這只證明代理 footprint，不等於
Bambu Studio 的真實 toolpath 已通過。

### 脫模間隙的上限是床（第十四輪）

使用者回報「支撐難拆、表面粗糙、拆的時候把 PCIe 三根細桿一起扯斷」。
第十三輪的 preset 把 `support_object_xy_distance` 覆寫成 **0.2**（Bambu 原廠 0.35）、
`support_interface_top_layers` 覆寫成 **0**，繼承來的 top/bottom z 間隙又只有 **0.16**
（＝一個層高）—— PETG 的層間與側向黏著比 PLA 強得多，這三個加起來等於把支撐**焊**在件上。

但支撐是印出來的料，也要佔床。往上開的空間被 A1 卡死：

| xy 間隙 | Chassis 加支撐佔床 | 餘量/邊 | 門檻 0.75 |
|---:|---|---:|---|
| 0.20（第十三輪） | 253.92 × 254.09 | 0.96 | 過 |
| **0.35（現役＝原廠值）** | **254.22 × 254.39** | **0.81** | 過 |
| 0.45（一度採用） | 254.42 × 254.59 | 0.71 | **不過** |

所以脫模餘裕改由**不佔床**的三個參數補：top/bottom z 間隙 0.16 → **0.32**（＝ 2 層）、
接觸面 0 → **1 層**（下表面才有連續線支撐，不再是 2.5 mm 間距的稜）、
`support_style` grid → **snug**（貼合輪廓，不再把整個窗填成一塊卡在三根肋之間的格柵）。
底接觸面仍留 0 —— 那一面是壓在件上的，加了最難拆。
回歸測試 `test_支撐外脹量受A1床餘量限制` 把這條衝突寫成斷言。

## 三份 process preset

檔案位於 `列印設定/`，JSON 與 `.info` 必須同 basename：

- `3DP-MATX 機殼件 0.16 支撐`
- `3DP-MATX 機殼件 0.16 無支撐`
- `3DP-MATX 主板螺絲 0.12`

`.info` 含目前 Bambu 帳號 metadata，不是跨帳號通用安裝檔。JSON 的 basename、`name`、
`print_settings_id` 與 `PRINT_PLAN` 引用由 `腳本/驗切片設定.py` 雙向比對。

### 機殼件 0.16 支撐

| 類別 | 鎖定值 |
|---|---|
| 層高 | `0.16` |
| 牆 | `wall_generator = arachne`、`wall_loops = 3` |
| 填充 | `40%`、`gyroid` |
| 支撐 | `enable_support = 1`、`normal(auto)`、`grid` |
| 支撐間距 | object XY `0.2`、expansion `0` |
| 支撐介面 | top `0`、bottom `0` |
| Raft | layers `0`、first-layer expansion `0` |
| 床附著 | `no_brim`、brim width `0`、skirt loops `0` |

### 機殼件 0.16 無支撐

與上表相同的 0.16 mm、3 walls、40% gyroid、arachne 與床附著設定，但
`enable_support = 0`。用於 Front、PCIeBlank、PCIeBar；三者正確姿態的懸空分別是
683.4、0.0、110.3 mm²——Front 那 683 mm² 是進氣柵與按鈕孔的上緣（都是短跨距，
可橋接），PCIeBar 那 110 mm² 是沉頭凹與壓舌的下側。開支撐只會堵住前柵或增加無用料。

### 主板螺絲 0.12

| 類別 | 鎖定值 |
|---|---|
| 層高 | `0.12` |
| 牆 | `wall_generator = arachne`、`wall_loops = 3` |
| 填充 | `100%` |
| 支撐 | `enable_support = 0` |
| 床附著 | `no_brim`、brim width `0`、skirt loops `0` |

MB_Screw 的 14.9 mm² 懸空是梯形外牙下側；支撐長進牙谷會破壞只有 0.20 mm 單邊間隙的
旋合面，因此必須關閉。六角頭平面貼床，螺紋軸朝上。

## 為何禁止 tree、brim 與自動 raft expansion

- `tree(auto)` 分枝可按 45° 往外斜；代理 footprint：
  - Chassis **605.92 × 602.89**。
  - Top **256.48 × 253.35**。
  - Rack **455.47 × 455.47**。
- `CASE_W = 252.68` 在 256 床上裸件只剩 1.66 mm/邊，5 mm brim 必定超床。
- `raft_first_layer_expansion = -1` 是自動值；舊版真 G-code 曾量到支撐首層額外外擴
  2.9–4.0 mm，所以即使 `raft_layers = 0` 仍須明寫 `0`。

因此三份 preset 都明寫：

```text
brim_type = no_brim
brim_width = 0
skirt_loops = 0
raft_layers = 0
raft_first_layer_expansion = 0
```

支撐 preset 另明寫：

```text
support_type = normal(auto)
support_style = snug
support_threshold_angle = 30      # ＝ 參數.SUPPORT_THRESHOLD_ANGLE（45° 特徵才算數）
support_expansion = 0
support_object_xy_distance = 0.35 # 上限由 A1 床餘量卡死
support_top_z_distance = 0.32     # = 2 × 0.16；PETG 一層會焊住
support_bottom_z_distance = 0.32
support_interface_top_layers = 1
support_interface_spacing = 0.5
support_interface_bottom_layers = 0
```

## 切片前後守門

```text
python 腳本\列印擺位.py --best
python 腳本\驗切片設定.py
```

兩支腳本分別證明 STL／支撐代理 footprint 與 preset 靜態設定。`驗切片設定.py` 還會以
同一個 Bambu Studio 安裝根目錄的 profile 與 `BambuStudio.dll` 驗 key／enum，避免拼錯值
被 Studio 靜默忽略。

第十四輪 **Bambu Studio 真實切片與真 G-code 由使用者驗證，目前尚未通過這一層**。
取得明確的 R13 G-code 後可逐檔檢查真正擠出路徑：

```text
python 腳本\驗切片gcode.py <明確的.gcode路徑>
```

機器吐料、擦嘴與延時攝影停車不計；模型、支撐、raft、brim 的實際擠出都必須留在
256 × 256 床內。第十一輪 G-code 只適用舊四件式機殼，不能拿來證明第十四輪。

## 材料與批次

- 使用 Bambu Generic PETG 作起點；品牌溫度、流量與收縮率依實際耗材校正，不在幾何
  process preset 硬編碼。
- Chassis、Top、Front、Rack 與 Tray 互相配合，應使用同料、同批參數；250 mm 跨距上
  0.1–0.2% 批次收縮差就是 0.25–0.50 mm，足以吃掉 0.30 mm/邊滑配。
- Chassis 與 Front 的床邊餘量小，必須確認床平整、清潔與首層穩定；不要用 brim 補救。
- 支撐拆除後刮平滑槽、承載唇與導向面，再試裝；0.30 mm 滑配不能容忍厚毛刺。
- 不預先套 `xy_contour_compensation`；先以 0 印配合件，只有實測偏差後才校正。

## 建議先試印

1. `MB_Screw ×1` 與一個盲內牙測試座：確認工作相位可手緊旋入兩圈，強度與拆裝手感合格。
   同一顆螺絲第十三輪起也鎖 PCIeBar（夾持厚同為 `PCB_T`，鎖點處有沉頭凹）。
2. **PCIe 窗那一段**：第十三輪把四個開孔的頂改成 45° 尖頂，目的就是讓切片器
   **不生支撐**——先確認 Bambu Studio 真的沒有在那四個槽裡長支撐塔。
3. `HDD_Tray ×1`：確認 SFF-8301 底孔與 #6-32×1/4" 穿入量。
4. Rack／Tray 局部配合與 Top／Front detent：確認 PETG 的 0.30 mm 滑配與可拆保持力，
   以及碟架橫樑坐上承托肩後的實際下沉量（設計間隙 0.30 mm）。

這些仍屬實印工作；腳本、FreeCAD 幾何與 process preset 通過不能取代它們。
